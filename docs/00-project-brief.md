## What this is

A personal, local-only app for following a hand-picked set of YouTube channels without ever
visiting youtube.com's homepage, recommendations or sidebar. Single user, runs under Herd,
never deployed.

## The three rules that make this app what it is

These are not preferences. Code that breaks them is wrong, however reasonable it looks.

1. **Archived metadata is immutable.** A video's `title`, `description` and archived thumbnail
   are written once at first ingest and never updated. Uploaders retitle and re-thumbnail
   videos days later to chase the algorithm; this app deliberately does not follow them. A
   refresh skips every video it has already seen. `videos.list` is called without
   `part=snippet` specifically so the newer title isn't even in the response. Durations, live
   status and availability *are* updated — metadata about the video, not its presentation.

2. **Shorts never appear.** Not behind a toggle, not in a tab. Detection is a duration gate
   plus a `HEAD` probe of `youtube.com/shorts/{id}` with a `<= 60s` fallback. If detection
   genuinely can't answer (`is_short IS NULL`), the video is **shown** — an unknown never
   silently swallows something wanted.

3. **Nothing suggests another video.** No recommendations, no related content, no autoplay, no
   infinite scroll, no view counts, no unread badges. Ordering is `published_at DESC` and
   nothing else. The one exception is a single explicit "Next unwatched from this channel"
   button on the end-of-video panel.

## Key decisions already made

Settled — don't relitigate without a reason. Full list in
[07-open-questions.md](07-open-questions.md#explicitly-settled-for-the-record).

- **Livewire 4 single-file page components + Flux Free + Tailwind v4.** No new dependencies,
  Composer or npm — the whole design fits what's already installed.
- **Fortify auth kept**, single user, everything behind `auth` (not `verified`). Registration
  closed after the one account exists.
- **SQLite**, and **synchronous refreshes** via `RefreshChannel::dispatchSync()`. There is no
  queue worker; requiring one is the most likely way for this app to appear broken.
- **RSS is the discovery backbone** (free, no quota); the Data API is enrichment only. Adding
  a channel imports ~15 videos and does not backfill history.
- **Videos and channels are kept forever.** Only `refresh_runs` are pruned.
- **Disable, not delete**, is the primary way to stop following a channel.
- **Thumbnails archived locally** (`maxresdefault` → `mqdefault`) and served by a route, not
  `storage:link` — symlinks are a Windows trap.
- **AI runs locally through Ollama** (`laravel/ai`, default `qwen3.5:4b`), no key, optional
  like every other dependency. Its one job so far is the weekly pick: on a channel you have
  switched to it, it may only *reduce* what that channel sends you. It never adds, reorders
  or recommends. See [04-routes-and-ui.md](04-routes-and-ui.md#picking-a-channels-week).

## Conventions

The Laravel Boost guidelines in `CLAUDE.md` / `AGENTS.md` govern general style. Project
additions:

- **Namespacing:** YouTube-facing services in `App\Services\YouTube\`; orchestration in
  `App\Services\`; value objects in `App\Support\`; enums in `App\Enums\`; domain exceptions
  in `App\Exceptions\`.
- **Every external call goes through `Illuminate\Support\Facades\Http`** so `Http::fake()`
  covers the whole surface. `Http::preventStrayRequests()` is on in `tests/Pest.php`.
- **All tuning belongs in `config/calm-tube.php`.** The `.env` surface is exactly one key:
  `YOUTUBE_API_KEY`. The app must boot, migrate and run without it.
- **Degrade, never block.** Every external dependency can fail. Missing key, exhausted quota,
  dead feed, changed YouTube behaviour — each reduces what the app knows and never stops it
  working. The degradation table is in
  [02-architecture.md](02-architecture.md#error-handling-and-degradation).
- **One feed definition.** All exclusion rules live in `Video::scopeInFeed()`. Never hand-roll
  those `where` clauses at a call site.
- **Nullable timestamps over booleans** for state: `watched_at`, `hidden_at`,
  `unavailable_at`, `enriched_at`.
- **Logging** goes to the `calm` channel with `channel_id` and `video_id` context.

## Running it

```bash
composer run dev          # serve + vite + queue listener + logs
php artisan schedule:work # second terminal, only for unattended hourly refreshes
```

Manual refresh buttons exist precisely because the scheduler usually won't be running:
"Refresh all" on the feed, "Refresh this channel" on channel pages.

```bash
php artisan calm:refresh              # all enabled channels
php artisan calm:refresh --channel=UC…
php artisan calm:enrich               # retry anything missing API data
```

## Before finishing any change

vendor/bin/pint --dirty --format agent
